# Keep README and docs in sync with code changes

Documentation is not auto-generated in this repo (only `public/release-notes.json`
is, via `scripts/generate-release-notes.mjs`). After changing code, update the
affected docs yourself. Do not require the user to ask for it.

## When to run

Run after you finish a logical set of edits that changes anything user- or
developer-facing:

- Features or UX behavior (templates, editing, AI modes, job match, i18n, themes)
- `package.json` scripts, dependencies, or the Node version requirement
- Environment variables (`.env.example`)
- API routes under `src/app/api/**`
- Electron packaging or Docker setup

Skip for internal-only refactors, tests, or changes with no doc-visible effect.

## What to update

Map the change to the smallest set of docs. The root `README.md` is the
user-facing entry point; `docs/*.md` is module-level detail. Keep both
consistent when relevant.

| Change area | Update |
|-------------|--------|
| Features, highlights, tech stack, commands, prerequisites, env vars, Electron/Docker | `README.md` |
| Architecture, tech stack, directory layout | `docs/overview.md` |
| DB schema, providers, repositories | `docs/database.md` |
| Resume model, nodes, patches | `docs/resume.md` |
| Templates (add/remove/rename) | `docs/templates.md` + template list in `README.md` |
| AI modes, providers, AgentScope/LangChain, skills | `docs/ai.md` |
| Job fit tool | `docs/job-match.md` |
| Pages, components, server actions | `docs/frontend.md` |
| HTTP API routes | `docs/api.md` |
| Locales, themes, settings | `docs/i18n-and-settings.md` |
| Electron runtime/packaging | `docs/electron.md` |
| Release-notes generation | `docs/release-notes.md` |

If you add or remove a `docs/*.md` file, also update the index tables in
`docs/README.md` and `AGENTS.md`.

## Workflow

1. Identify what the change alters (features, commands, env vars, deps, routes).
2. Verify facts against the source, not memory:
   - Scripts and deps → `package.json`
   - Env vars → `.env.example`
   - Templates → `src/templates/resume/registry.ts`
   - API routes → `src/app/api/**`
   - Locales/themes → `src/lib/i18n.ts`
3. Edit only the docs that are actually affected. Match existing tone, headings,
   and formatting; keep changes concise.
4. Preserve internal links and the `docs/` index tables.
5. In your final summary, list which docs you updated and why.

## Anti-patterns

- Do not rewrite whole docs; make targeted edits.
- Do not invent commands, env vars, or features not present in the code.
- Do not touch `public/release-notes.json` (generated by build).
- Do not add time-sensitive notes ("as of ...") to the docs.
